The Goldfish Problem: Why AI Agents Forget Everything Between Conversations

You've built an AI agent that forgets everything between conversations, re-discovering the same information and making the same mistakes. This is the "Goldfish Problem," a common pain point for developers working with large language models (LLMs). Let's tackle it head-on.

When you decouple memory into distinct components – short-term buffers for execution, episodic logs for experience, and semantic stores for facts – you get systems that actually learn, stay within data limits, and don't suffer from context pollution. MrMemory handles this nicely:


from mrmemory import MrMemory

client = MrMemory(api_key="your-key")
client.remember("user prefers dark mode", tags=["preferences"])
results = client.recall("what theme does the user like?")

This dedicated memory store prevents irrelevant memories from polluting the context, giving you the hooks you need for privacy compliance later.

Another approach is to weight recent memories higher in retrieval scoring. This ensures your AI agent prioritizes relevant information over stale data:


client = MrMemory(api_key="your-key")
results = client.recall("what theme does the user like?", weights={"recent": 1, "stale": 0})

Time-To-Live (TTL) and eviction policies can automatically expire stale data. This prevents overloading your context with irrelevant information:


client = MrMemory(api_key="your-key")
client.set_ttl("user prefers dark mode", 30 * 24 * 60 * 60) # 30 days

While Mem0, Zep, and MemGPT offer some memory management features, they lack the comprehensive anti-pollution patterns found in MrMemory. For instance:

  • Mem0 relies on a larger context window, which can lead to token costs ballooning.
  • Zep is self-hosted only, limiting its accessibility.
  • MemGPT has limited support for TTL and eviction policies.

Anti-pollution patterns are essential for preventing memory pollution in AI agents. By decoupling memory into distinct components, weighting recent memories higher, and using TTL and eviction policies, you can improve recall accuracy, reduce token costs, and create more effective AI systems.
