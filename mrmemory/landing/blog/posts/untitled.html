Reducing AI Token Costs with Memory Compression

As AI agents become increasingly ubiquitous, the costs associated with their maintenance and operation are skyrocketing. One of the biggest expenses? AI token costs. We'll explore the issue of token costs and present several methods for reducing them using memory compression.

The Naive Agent Memory Problem

Most agent frameworks use a naive file-memory injection approach, which scales linearly with usage. This means that as your memory store grows, so does the number of prompt tokens required for each inference call. We'll illustrate this issue with an example. Suppose you have a 24-entry memory store, and you want to retrieve a specific piece of information from it. Naive file-memory injection would require injecting all 24 entries into the prompt, resulting in a whopping 594 tokens. But what if you used a retrieval-based memory architecture? You could reduce that number to just 166 tokens, saving 72% (based on the same query and model).

Compression Techniques

Several compression techniques can help reduce token costs:

  • Hierarchical summarization: Create summaries of your memory store at multiple levels to enable more efficient information retrieval.
  • Ebbinghaus eviction: Remove the least-recently-used entries from your memory store to reduce the number of tokens required for each inference call.
  • Embedding quantization: Reduce the precision of your embeddings to enable more efficient storage and retrieval of information.
  • Jaccard self-curation: Use the Jaccard similarity metric to identify and remove duplicate memories from your store, reducing the number of tokens required for each inference call.
  • Hot/cold caching: Store frequently-accessed information in a separate cache to reduce the number of tokens required for each inference call.

Implementation with MrMemory
